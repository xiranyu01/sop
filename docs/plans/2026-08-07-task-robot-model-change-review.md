# 任务 SOP 机型改动说明

更新时间：2026-08-07

## 结论先说

当前本地分支不能称为“只增加生产需求项弹框里的机型过滤”。这版同时包含上一轮任务 SOP 机型管理和任务复制的改动。

因此：

- 不会删除已有客户、物料、场景、任务 SOP 或需求数据。
- 会修改数据库结构，并在迁移时写入已有任务的机型元数据。
- 选择或修改任务 SOP 的适用机型时，会更新任务 SOP 当前资源的管理字段、更新时间和 ETag。
- 当前 YAML 导出代码没有把机型绑定写入 YAML，现有 YAML 字段结构和内容来源不变。
- 如果目标是只上线“生产需求项选择任务 SOP 时按机型过滤”，需要先把本轮前端筛选改动单独拆出来，再部署。

## 当前工作区包含的改动

### 1. 任务 SOP 复制

支持从任务 SOP 详情复制任务：

- 新任务版本从 `0.0.1` 草稿开始。
- 名称使用原任务名称加“副本 1”“副本 2”等后缀。
- 副本序号由数据库计数器分配，不扫描全部任务和归档任务。
- 复制出的任务保留任务正文和附件引用，但拥有新的资源身份。

相关接口：

- `POST /api/resources/taskSops/:name/copy`

### 2. 任务级适用机器人型号

任务 SOP 可以选择多个适用机器人型号，所有版本共用这组机型：

- 任务 SOP 详情页可以编辑机型。
- 场景任务列表显示适用机型。
- 场景目录可以按机型筛选任务。
- 没有配置机型的任务视为通用任务。
- 机型显示使用机器人型号的 `model` 字段，不再拼接 `brand`，避免重复显示。
- 保存时使用请求队列和 ETag，减少连续选择造成的并发冲突。

相关接口：

- `POST /api/resources/taskSops/:name/robot-models`

### 3. 生产需求项选择任务 SOP 的机型筛选

这是本轮最后追加的前端功能：

- 选择任务 SOP 弹框增加适用机器人型号下拉筛选。
- 候选任务列表增加“适用机型”列。
- 支持显示具体型号和“全部机型”。
- 支持按任务名称或场景名称搜索。
- 选择具体机型时，绑定该机型的任务和未绑定机型的通用任务都会显示。
- 只使用已有任务版本中的机型绑定，不改变生产需求项引用的任务 SOP 版本。

## 数据库影响

本地分支新增迁移文件：

`migrations/0005_task_sop_copy_and_robot_models.sql`

迁移包含以下操作：

### 新增任务复制计数器表

`SOP_TASK_SOP_COPY_COUNTERS`

用于分配“副本 1”“副本 2”等序号，避免每次复制扫描全部任务。

### 新增任务与机型关系表

`SOP_TASK_SOP_ROBOT_MODELS`

保存任务 SOP 和机器人型号资源名之间的关系，并增加机器人型号索引。

### 修改现有资源表

在 `SOP_CURRENT_RESOURCES` 增加：

`task_robot_models_json TEXT NOT NULL DEFAULT '[]'`

### 迁移已有任务

迁移最后会从已有任务的 ProtoJSON 中读取 `robotModels`，回填到：

- `task_robot_models_json`
- `SOP_TASK_SOP_ROBOT_MODELS`

这不是破坏性删除，但确实会改变已有数据库的结构和部分投影数据。因此，不能对当前版本作出“不会改已有数据库”的承诺。

## YAML 影响

当前导出实现位于：

- `server/export/bundle.ts`
- `server/export/yaml.ts`

本轮没有修改 YAML 序列化逻辑，当前 `server/export/yaml.ts` 也没有读取任务根对象的 `robotModels` 字段。机型绑定属于管理元数据，不会出现在任务 SOP YAML 中。

因此在以下前提成立时，已有 YAML 的字段结构和内容不变：

- 不修改任务 SOP 正文。
- 不修改物料、场景、全局字段等 YAML 数据源。
- 只保存任务级机型绑定。

需要注意：保存机型仍会更新任务 SOP 当前资源的 `updateTime` 和 `etag`，但不会创建新的 SOP 版本，也不会改写已确认版本快照。重新导出同一个已确认版本时，YAML 内容不应因机型筛选而变化。

## 当前版本与“只上线机型过滤”的差异

如果直接把当前工作区发布，实际会同时发布：

1. 任务复制能力。
2. 任务级机型管理。
3. 数据库迁移和新的 D1 表、字段、索引。
4. 任务列表和场景目录的机型展示与筛选。
5. 生产需求项选择任务 SOP 弹框的机型筛选。
6. 机器人型号显示文案调整为只显示 `model`。

如果只想发布生产需求项弹框筛选，则应只保留：

- `src/App.tsx` 中候选任务筛选、机型列和下拉框的前端改动。
- `src/App.css` 中候选机型筛选框的样式改动。

并且不应发布以下改动：

- `migrations/0005_task_sop_copy_and_robot_models.sql`
- `proto/coscene/sop/v1alpha1/task_sop.proto` 的机型字段。
- `server/` 中任务复制、机型保存和 D1 投影代码。
- `src/api/client.ts` 中对应的新 API。

这样才可以把本次发布明确限定为前端过滤展示，不触碰数据库写入逻辑，也不会改变 YAML 导出。

## 发布前建议

建议先决定发布范围：

### 方案 A：发布完整本地分支

接受数据库增加表、字段和回填，发布任务复制、任务级机型管理及需求项机型筛选。

上线前需要：

- 备份 D1。
- 在测试数据库执行迁移并验证回滚预案。
- 验证已有任务的机型为空时仍显示为通用任务。
- 对比同一个已确认任务 SOP 发布前后的 YAML。

### 方案 B：只发布生产需求项机型筛选

只发布前端筛选相关文件，不执行 `0005` 迁移，不发布机型保存 API。这个方案最符合“只增加机型过滤”的描述，风险和影响范围也最小。

当前建议先采用方案 B，等任务级机型管理和任务复制一起验收后，再作为完整版本发布。
